# 组织管理与权限

在项目根目录执行：

```sh
node server/scripts/seed-default-menus.js
```

脚本可重复执行，在现有数据库补齐用户管理、部门管理、角色管理、内容助手菜单，
把四个页面授权给角色 0（超级管理员），把部门、角色页授权给角色 2（默认查看者）。
新环境需要先初始化 `server/db/init.sql` 和 `server/db/agent.sql`。

| 功能 | 超级管理员 | 查看者 |
| --- | --- | --- |
| 用户列表 | 查看、筛选、分页 | 禁止；仅可读取本人资料 |
| 部门、角色列表 | 查看、筛选、分页 | 查看、筛选、分页 |
| 用户、部门、角色新增/编辑/删除 | 允许，受内置角色及关联保护约束 | 禁止，HTTP 403 |
| 角色菜单配置 | 允许；自动补齐父菜单 | 禁止 |
| 内容助手 | 仅管理自己的会话并调用模型 | 禁止，HTTP 403 |

其他角色可按需分配部门、角色等菜单。用户管理和内容助手仅管理员可用，
旧数据库中的遗留菜单授权也受此限制。写接口独立检查超级管理员身份。
账号每次调用接口时会重新校验是否启用，授权更新后前端刷新会重新同步本人资料和菜单。

部门支持名称、负责人筛选及父子层级；不能将父节点设为自身或后代，
存在子部门或关联用户时不能删除。角色支持名称筛选、用户数量及菜单展示；
存在关联用户时不能删除。角色 0、2 是内置角色，禁止编辑或删除，保证默认注册账号权限稳定。

## 演示账号

- 在演示服务器上初始化独立的 MySQL 数据卷。Compose 会加载基础数据和示例文章，真实的用户、手机号及聊天历史留在原环境。
- 保持 `ALLOW_PUBLIC_REGISTRATION=false`。在项目根目录运行
  `docker compose --env-file .env.compose.local exec api node scripts/create-admin.js`
  创建管理员。用管理员登录，在用户管理中为访问者建立「查看者」账号。
- 向访问者提供查看者账号。内容助手由管理员登录演示，演示环境的模型密钥保存在服务端。
- 本地需要回归自助注册时，可在本地环境文件明确写入 `ALLOW_PUBLIC_REGISTRATION=true`，重建 API 容器以应用配置。

## 接口

新页面使用 `/api/departments/list`、`/api/roles/list` 分页查询，
`POST /api/departments`、`POST /api/roles` 新增，
`PATCH /api/departments/:id`、`PATCH /api/roles/:id` 编辑，
`DELETE /api/departments/:id`、`DELETE /api/roles/:id` 删除。
部门编辑提交 `name`、`leader`、`parentId` 完整表单；角色编辑提交 `name`、`menuIds`。
`GET /api/departments/options` 返回未分页的部门层级选项。
原有 `/api/department/list`、`/api/role/list` 保留给用户编辑表单的下拉选项。

## 本地检查

```sh
npm run build
node server/scripts/test-register.js
node server/scripts/test-organization.js
```

集成检查连接本地数据库，创建随机测试数据并在结束时清理。
组织检查不调用付费模型，覆盖菜单权限、只读限制、管理员 CRUD、层级防环、
关联删除保护、动态授权、停用账号以及助手会话隔离。
